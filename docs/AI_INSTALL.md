# Передать установку нейросети

Эта страница — сценарий работы помощника. Команды и объяснения находятся в
[полной инструкции](INSTALL.md); критерии готовности — в [чек-листе](ACCEPTANCE.md).
Она подходит и для ссылки на GitHub, и для распакованного исходного архива релиза.

## Готовое сообщение

Скопируйте в новый чат этот текст вместе со ссылкой на репозиторий или архивом:

```text
Установи мне https://github.com/cherryofmind/keenetic-xhttp-bridge.
Сначала прочитай README.md, AGENTS.md, docs/AI_INSTALL.md, docs/INSTALL.md,
docs/SETUP.md, docs/ACCEPTANCE.md и SECURITY.md целиком.
Нужна схема: домашний Keenetic → мой сервер РФ → мой иностранный сервер,
выборочный обход для всей домашней сети и автоматическое обновление списков.

Собери недостающие исходные данные одним коротким списком. Доступные сведения
проверь сам через разрешённые инструменты. Выполняй установку по этапам,
проверяй результат каждого этапа и продолжай без повторных согласований
обычных действий в уже разрешённых пределах.

Действующий VPN сохраняй до проверки новой цепочки и подготовки отката.
Серверы не покупай, чужие задачи не меняй, накопители не форматируй и сеть
не перезагружай без отдельного разрешения на соответствующее действие.
Не отправляй мои ключи и рабочие конфиги в чат, GitHub или публичные сервисы.

Если у тебя нет инструментов доступа к моему оборудованию, прямо скажи об этом
и проведи меня по тем же этапам короткими блоками команд с проверкой вывода.
Не объявляй работу завершённой по одному status/HTTP-коду: проверь обычный
интернет, выбранные сайты, приложение, видео и устойчивость под нагрузкой.
В конце дай краткий результат, путь к закрытому отчёту и точный способ отката.
```

Нейросети нужны инструменты выполнения команд и доступ к вашему оборудованию,
чтобы делать изменения самой. Обычный чат без таких инструментов сможет объяснять
и проверять присланные обезличенные результаты. Один URL не предоставляет доступ
к роутеру или VPS. Физическое подключение USB и ввод пароля/2FA владелец выполняет
сам, если у помощника нет соответствующего разрешённого средства доступа.

## Первое действие помощника: собрать исходные данные

Не заставляйте владельца разбираться в технических деталях, которые можно прочитать
с оборудования. Спросите только недоступное. Не просите вставлять пароли и ключи в чат.

| Что выяснить | Как использовать |
| --- | --- |
| ОС управляющего компьютера, Python, SSH/SFTP, возможность локального запуска Xray | Выбрать команды PowerShell либо POSIX; не запускать команды одного shell в другом |
| Модель, KeeneticOS, архитектура, RAM/свободное место | Совместимость Xray/XKeen, USB/Entware; MIPS-параметр не включать наугад |
| USB: конкретный накопитель, содержимое, EXT4, монтирование `/opt` | Не форматировать существующие данные; установка должна пережить загрузку |
| Авторизованный доступ к Keenetic и отдельно к Entware shell | Порт и учётная запись могут отличаться от CLI Keenetic |
| РФ VPS и иностранный VPS: кто есть кто, ОС/архитектура, SSH, важные сервисы, firewall | Найти свободные порты, не занять чужие задачи, использовать только разрешённые узлы |
| Прежний VPN, его интерфейс и экспорт; DNS по каждому сегменту; IPv6 | Подготовить реальный откат и исключить зависимость DNS от старого туннеля |
| Выборочные сайты или весь трафик; вся LAN или выбранные устройства | В этом руководстве стандарт — выборочные назначения всей LAN, не full tunnel |
| Как поддерживать связь при переключении | Запасной доступ, локальное управление и таймер отката |
| Срок аренды и бюджет уже имеющихся VPS | Тестовый сервер не становится бессрочно оплаченным из-за завершения установки |

## Порядок выполнения и условия перехода

1. **Инвентаризация.** Прочитать состояние, показать краткую схему и список
   изменений. Записать приватный `install-report.local.md` по шаблону из чек-листа.
2. **Основание для отката.** Сохранить конфигурацию, отдельный VPN-экспорт, DNS,
   существующие файлы/службы/расписание. Проверить доступ к копии вне роутера.
3. **Ключи и серверы.** Следовать INSTALL: локальная генерация → иностранный выход
   → РФ-вход. Проверить версии, конфиги, слушающие порты и журнал. Домашний VPN пока прежний.
4. **Один клиент.** Проверить всю цепочку до изменения LAN. Нужны прикладные запросы
   через клиент и подтверждение иностранного выхода, а не только TCP до РФ.
5. **Роутер.** Подготовить Entware/XKeen, файлы, geodata, исключения, порты и DNS;
   проверить весь confdir. Не заменять существующий рабочий Xray без разбора конфликтов.
6. **Страховка.** Проверить применимость rollback и таймер. Без исходного OpenVPN
   использовать собственный проверенный план восстановления, а не пример из пакета.
7. **Переключение.** Пользовательское «установи» не означает право терять единственный
   канал управления. При сохранённом канале и согласованном переключении выполнить его,
   затем заполнить чек-лист. Если связь/приложения сломались — откатить свой этап.
8. **Закрепление.** Только после проверки отключить таймер маркером, включить автозапуск,
   сохранить настройки, добавить одно обновление списков. Проверить перезагрузку,
   когда она разрешена, и отдельно указать, если она отложена.

Запрашивать разрешение повторно на уже разрешённый шаг не нужно. Покупка, стирание
данных, вмешательство в занятый сервер и потеря единственного доступа требуют
конкретной авторизации, если её ещё нет. Если владелец отошёл, продолжайте независимые
проверки, а зависимый опасный шаг оставьте до его ответа.

## Как работать с ошибками

- Отказ входа/2FA: попросить владельца войти, не сбрасывать доступ.
- Нет `/opt`, нужного Netfilter или подходящего бинарника: устранить именно эту
  предпосылку; основной VPN не трогать.
- Xray не принимает JSON: читать локальную ошибку, исправлять источник и повторять
  проверку. Не обходить проверку и не ставить случайно более старое ядро.
- РФ-порт доступен, но цепочка не работает: сравнить оба плеча и логи; не открывать
  все порты и не отключать firewall.
- CPU, потери или просадки: использовать [DIAGNOSTICS.md](DIAGNOSTICS.md), один
  меняемый фактор за тест; новый хостинг не считать исправлением без сравнения.
- Ответ WAF/Cloudflare: подтвердить в браузере. Ответ 403 не равен обрыву сети,
  но и не доказывает, что пользователь может пользоваться сервисом.

## Как сообщить итог

Указать отдельно: что подготовлено; что реально установлено; какие устройства
и сайты проверены пользователем; сколько длилась нагрузка; сохранялся ли прежний
доступ; где закрытые копии и команда отката; проверена ли загрузка после reboot;
срок оплаты обоих VPS. Непроверенное обозначить как непроверенное.

Это инструкция воспроизведения, а не обещание, что любая модель, любой Keenetic
и любой провайдер пройдут её автоматически. Поддерживаемый исходный стенд и
пределы испытаний перечислены в README.
