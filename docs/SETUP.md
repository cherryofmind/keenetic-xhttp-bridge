# Подготовка, переключение и откат

Это краткая техническая памятка. Для первой установки используйте
[полную последовательность с командами и объяснениями](INSTALL.md),
для установки нейросетью — [AI_INSTALL.md](AI_INSTALL.md).
Результат фиксируйте по [чек-листу](ACCEPTANCE.md).

Этот выпуск — инструкция для оператора и генератор профилей. Он не форматирует накопители, не меняет firewall и не выключает действующий VPN автоматически. Рассчитан на Entware, штатный XKeen 2.1 и DNS-профиль Keenetic с обычными DNS53 upstream. При другой системе DNS сначала адаптируйте восстановление.

## 1. До изменений

1. Сохраните конфигурацию Keenetic, отдельный исходный OpenVPN-профиль, идентификатор интерфейса и фактические DNS. Running-config не заменяет отдельный экспорт OpenVPN с сертификатами.
2. Проверьте свободную память, наличие USB/EXT4, Entware, Netfilter и TPROXY. Для KN-1713 во встроенном хранилище может не хватать места. Работа USB необходима после перезагрузки.
3. Для старого OpenVPN сохраните назначение интерфейса и маршрут провайдера по умолчанию. VPN не должен становиться default gateway, если нужна выборочная схема.
4. На серверах проверьте, что порты свободны и там нет важных сторонних задач. Не заменяйте существующие сервисы Xray/OpenVPN и не очищайте firewall.

Скопируйте `configs/rollback.example.json` в защищённый локальный файл и заполните **своими исходными** интерфейсом, DNS-профилем и серверами. Значения примера не являются снимком вашего роутера.

## 2. Новые ключи и локальные файлы

Установите Xray из [официальных релизов](https://github.com/XTLS/Xray-core/releases/tag/v26.10.29) для своей архитектуры, проверьте контрольную сумму релиза и `xray version`. Здесь нет бинарников или общего клиентского ключа.

Запустите команды из README. `init` локально вызывает `xray vlessenc` и `xray x25519`, создаёт два разных UUID и случайные path/short ID. Ничего не отправляет серверам. Файлы настроек и результат содержат секреты, резервируйте их отдельно от Git.

Проверьте `server_name`: сайт-цель REALITY должен быть достижим с иностранного сервера и совместим с вашей версией ядра. Домен в примере не является гарантией против блокировок.

Собственные домены и IP храните в локальных файлах:

```sh
python tools/render.py render --domains custom-domains.local.txt \
  --ips custom-ips.local.txt --output generated/site-1
```

Не публикуйте эти файлы, если в них личные назначения. Указанные домены включают поддомены. IP-исключения применяются к перехваченным портам; это не безусловный маршрут всего трафика к адресу.

## 3. Два сервера

На каждом сервере установите официальный Xray как `/usr/local/bin/xray`, конфигурацию в `/etc/home-xray/` с правами root:root 0600. Профили не взаимозаменяемы:

- РФ: `generated/server/entry.json`, сервис `systemd/home-xray-entry.service`.
- Зарубежный: `generated/server/exit.json`, сервис `systemd/home-xray-exit.service`.

Сначала выполните `xray run -test -config /etc/home-xray/entry.json` или `exit.json` на соответствующем узле. Затем `systemctl daemon-reload` и `systemctl enable --now ИМЯ.service`. Сохраните прежние unit/config перед заменой, если используете совпадающее имя.

В облачном и системном firewall разрешите TCP вход на РФ-порт (по умолчанию 8080) и доступ РФ → иностранный REALITY-порт (55443). Сохраняйте SSH и остальные правила. DNAT, изменение `ip_forward` и отключение firewall для этой прикладной цепочки не нужны.

На домашнем участке нет внешнего TLS: шифрование обеспечивает обязательный VLESS Encryption. `encryption=none` для этого входа недопустим. На втором плече используется REALITY. Открытый порт и TLS/HTTP-ответ не подтверждают реальную работу сайтов.

## 4. Сначала один мобильный/настольный клиент

Импортируйте `generated/mobile/profile.txt` в совместимый клиент. Для Happ 6.2.0 App Store на дату проверки указывал Xray 26.10.21; это ядро отдельно проверялось на ПК. Поддержку конкретного импортера и мобильного провайдера проверяйте на устройстве. JSON-резерв — `generated/mobile/client.json`.

Этот профиль по умолчанию направляет трафик клиента через VPN; домашний роутерный профиль — выборочный. Загрузите несколько сайтов, отправьте сообщение, воспроизведите видео несколько минут, создайте новые подключения после простоя. Через мобильную сеть повторите тест отдельно.

Не экспортируйте MIPS/Linux customSockopt в телефон. Vision по умолчанию подавляет UDP/443, чтобы браузеры переходили на HTTPS/TCP; это описано в документации Xray и не является отдельным доказательством блокировки провайдером.

## 5. Keenetic / XKeen

Установите [XKeen по документации разработчика](https://github.com/jameszeroX/XKeen). При установке выберите Xray для архитектуры роутера, отключённый автозапуск и отключённое автоматическое обновление ядра. Версия 2.1 использует актуальные Netfilter-модули KeeneticOS 5+. Не заменяйте существующие пользовательские конфигурации без их слияния и резервной копии.

На USB разместите:

| Файл | Куда |
| --- | --- |
| `generated/router/00-home.json` | `/opt/etc/xray/configs/00-home.json` |
| Re:filter `geosite.dat` | `/opt/etc/xray/dat/geosite_refilter.dat` |
| ZKeen `zkeen.dat` | `/opt/etc/xray/dat/geosite_zkeen.dat` |
| ZKeenIP `zkeenip.dat` | `/opt/etc/xray/dat/geoip_zkeenip.dat` |

Установку и проверку геофайлов выполняйте средствами XKeen. Их исходные URL приведены в THIRD_PARTY.md. В каталоге configs не должно оставаться конфликтующих шаблонных inbounds/outbounds; переместите их в резерв вне confdir, не удаляя свои старые профили.

В `/opt/etc/xkeen/ip_exclude.lst` добавьте IP **своего** РФ-входа и внешнего выхода, а также используемые прямые DNS. Так служебные соединения не зациклятся. IPv6 требует отдельной законченной схемы: в исходном стенде домашние IPv6-подключения были отключены, IPv6-обход блокировок не проверялся.

В `/opt/etc/xkeen/port_proxying.lst` исходный стенд использовал:

```text
22
80
443
3478
5222:5223
5228
19302:19309
```

Остальные порты идут обычной маршрутизацией ядра; игры не отправляются в США автоматически. Если сервису нужны другие порты, расширяйте список осознанно. TCP Redirect слушает все адреса для корректного REDIRECT, UDP TPROXY — loopback. Сохраняйте запрет входа с WAN к служебным портам и не открывайте LAN-прокси в Интернет.

```sh
XRAY_LOCATION_ASSET=/opt/etc/xray/dat xray run -test -confdir /opt/etc/xray/configs
```

## 6. Откат подготовить перед переключением

Скопируйте проверенный `rollback.json` и `scripts/rollback-router.sh` в `/opt/etc/home-xray/`, root-only. `chmod 700` для сценария, `chmod 600` для JSON. Он рассчитан на штатный namespace XKeen (`xkeen_rule`, таблица 111). При кастомном namespace адаптируйте сценарий заранее.

Сценарий останавливает XKeen, убирает его собственные правила, восстанавливает заданные DNS53 upstream и включает сохранённый OpenVPN. Не восстанавливает удалённый профиль и не отменяет чужие изменения.

Перед изменениями запустите страховочный таймер, перенаправив все потоки:

```sh
rm -f /opt/etc/home-xray/confirmed
nohup sh -c 'sleep 600; exec /opt/etc/home-xray/rollback-router.sh --if-unconfirmed' \
  </dev/null >/opt/etc/home-xray/guard.log 2>&1 &
```

Проверьте, что таймер жив и `sh -n` принимает сценарий. Не проверяйте откат выполнением на работающей сети без необходимости.

## 7. Переключение

1. Проверьте новый профиль и страховочный таймер; сохраните канал управления. Не ставьте второй Xray поверх уже запущенного.
2. Если старый AntiZapret подменял DNS, замените зависимые от него DNS на реальные доступные резолверы в системном и назначенном сегменту DNS-профиле. В исходном стенде применялись DNS Яндекса, но это не универсальное исправление проблем сети. Проверьте отсутствие зависимости от выключаемого туннеля.
3. Выключите **только сохранённый прежний** OpenVPN-интерфейс и сразу запустите `/opt/etc/init.d/S05xkeen start on`; проверьте ошибки и правила. Его тело, сертификаты и неактивные авто-маршруты сохраните. Выполните переход в пределах таймера.
4. Без VPN на самом устройстве проверьте прямой выход и выбранные сайты, ChatGPT/приложение, воспроизведение YouTube, новые соединения и CPU. Старые DNS-подмены могут оставаться в кэше приложений: перезапустите приложение/устройство, не закрепляйте CDN-IP навсегда.
5. После короткой успешной проверки создайте `/opt/etc/home-xray/confirmed`, чтобы старый таймер не прервал дальнейший тест. Проведите длительную приёмку с готовым ручным откатом. После неё включите автозапуск XKeen и сохраните конфигурацию Keenetic. Без маркера таймер попытается вернуть прежнее подключение.

После перезагрузки отдельно проверьте монтирование USB, автозапуск и сайты. Публикуемый пакет не проходил эту проверку на чистом устройстве.

## 8. Автоматические списки

Скопируйте `scripts/update-geodata.sh` в `/opt/etc/home-xray/update-geodata.sh`, сделайте исполняемым и выполните один контрольный запуск. Он использует штатный `xkeen -ug`, проверяющий размер и SHA-256, сохраняет предыдущие dat и возвращает их, если после обновления ядро не запущено. Пользовательский JSON с дополнениями не перезаписывается.

Добавьте одну строку в **существующий** crontab Entware, сохраняя другие задания:

```cron
23 4 * * * /opt/etc/home-xray/update-geodata.sh
```

Это 04:23 по часовому поясу самого роутера. В исходном стенде — МСК. Штатное обновление может кратко перезапустить Xray. Не включайте автоматическое обновление самого ядра одновременно с диагностикой.
